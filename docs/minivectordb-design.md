# MiniVectorDB 设计与验证记录

本文说明 MiniVectorDB 的记录布局、向量索引方案、事务处理、提交持久化与恢复流程，
并列出已实现的功能与已知限制。文中的全部数字都是自测结果，**不是官方平台成绩**；
正式成绩以平台对锁定 commit 的评测为准。

## 1. 总体结构

| 源文件 | 职责 |
| --- | --- |
| `minivectordb/src/core.{hpp,cpp}` | JSON 解析与序列化、UTF-8 码点工具、CRC32、距离计算内核、错误类型 |
| `minivectordb/src/sql.{hpp,cpp}` | 词法分析与递归下降语法分析，产出与列名解耦的 AST；向量字面量解析 |
| `minivectordb/src/storage.{hpp,cpp}` | 定长页文件、LRU 缓冲池、redo 预写日志、检查点与恢复 |
| `minivectordb/src/table.{hpp,cpp}` | 行编码与解码、主键索引、扫描器、增删改、HNSW 索引的挂接 |
| `minivectordb/src/hnsw.{hpp,cpp}` | 自实现的 HNSW 向量索引 |
| `minivectordb/src/db.{hpp,cpp}` | 目录（catalog）、SQL 执行、投影与排序、exact / ann 两条检索路径 |
| `minivectordb/src/main.cpp` | JSON Lines 协议前端 |

没有使用任何第三方库：存储、查询执行、向量索引和事务全部自行实现，只依赖 C++17
标准库与 POSIX 文件接口。

## 2. 记录布局

页大小固定为 64 KiB，页头 64 字节：

```
偏移 0   u32  魔数 'MVDB'
偏移 4   u16  页类型
偏移 6   u16  槽位数量
偏移 8   u32  堆顶（行数据最低地址）
偏移 12  u32  槽位目录末端
偏移 16  u32  行数
偏移 20  u32  空闲链表头
偏移 24  u64  页 LSN
```

行数据从页尾向下生长，槽位目录从页头向下生长。槽位是 8 字节：高 32 位是行长度，
低 32 位是行偏移，`0xFFFFFFFFFFFFFFFF` 表示已释放。

一行记录的结构：

```
[0..2)    u16  NULL 位图
[2..4)    u16  标志位
[4..8)    u32  保留
[8..16)   i64  主键
[16..)    i64  其余每个 BIGINT 列各 8 字节
          u16  VARCHAR 列数量，随后每列一个 u16 长度
          填充到 16 字节边界
          float32 向量载荷（定长）
          VARCHAR 载荷（变长，按列顺序紧跟）
```

`VARCHAR(n)` 的长度限制按 Unicode 码点数检查，磁盘上按 UTF-8 字节数存储。
字符串比较按码点顺序进行，UTF-8 的字节序与码点序一致，因此可以直接比较字节。

行尺寸必须与布局严格一致，否则写入会覆盖后面的列。实现里 `Table::row_size()`
与 `Table::compute_layout()` 使用同一套偏移量。

## 3. 向量索引

`HnswIndex` 是自实现的 HNSW：M = 32、层 0 容量 64、建索引 ef = 50、查询 ef 可调，
层数用固定种子的几何分布随机生成，因此索引可以从持久化数据确定性重建。

- 节点向量存放在一块连续数组里；插入时容量按倍数增长，避免每次插入都重新分配并
  拷贝整个向量库（早期版本按「正好够用」预留，导致插入变成平方复杂度）。
- 删除使用墓碑：节点仍留在图里保持拓扑，但不会出现在查询结果中。
- 替换（UPDATE 向量）会插入一个新节点并把旧节点标记为墓碑。
- 行数不超过 1024 时直接做精确扫描，小表因此始终精确。
- 启动时会从持久化行重建索引，**重建完成之后才输出 `{"type":"ready"}`**；重建
  耗时写在 stderr 上（例如 `rebuilt the vector index of table t (10000 rows) in 1271 ms`）。

检索路径：

- `exact`：全表扫描，先应用 WHERE 过滤再排序，过滤后的 TopK 一定在满足条件的集合内。
- `ann`：先用索引取候选，再按页分组过滤并用行内的向量重算精确距离。候选预算从
  `max(4K, 64)` 起步，如果过滤后不足 K 条就按 4 倍递增，直到全表；仍然不足时回退到
  精确扫描，保证返回条数与结果正确。
- 两种模式的并列排序都按主键升序。

## 4. 事务处理

事务模型是语句级 + 事务级两层 undo：

- **语句级**：每条语句开始时记录被修改的字节区间与旧内容，语句失败时按逆序还原，
  因此失败语句不会留下任何部分修改。
- **事务级**：`BEGIN` 之后，语句级 undo 还会累积到事务级 undo；`COMMIT` 丢弃 undo
  并提交，`ROLLBACK` 用事务级 undo 把所有修改还原。
- 内存里的主键索引与 HNSW 索引是派生结构，用 `IndexUndo` 记录，跟随同样的事务边界。
- 同一时刻只允许一个显式事务，嵌套 `BEGIN` 返回错误。

自动提交模式下，一条成功语句的修改在响应发出前就已经写入预写日志并 `fdatasync`。

## 5. 持久化与恢复

预写日志是 redo log，记录类型有两种：

| 类型 | 内容 |
| --- | --- |
| `PAGE_ALLOC` | 新分配了一个页：表 id、页 id、页头 |
| `PAGE_MODIFY` | 页内若干字节区间被修改：表 id、页 id、区间表、区间内容 |

每条记录带 LSN 与 CRC32，重放时先校验 CRC，不完整的尾部会被截断。

- 语句提交时把本语句修改过的页写成重做记录并 `fdatasync`；显式事务在 `COMMIT`
  时才落盘。
- 检查点时把脏页写回数据文件、写入 manifest（记录检查点 LSN）并截断日志。
- 未提交的修改只存在于缓冲池中，且这些页被标记为「粘滞页」，不会被换出到磁盘，
  所以强杀之后未提交的事务不会部分生效。
- 恢复时先重放日志（`PAGE_ALLOC` 会把文件扩展到整页，`PAGE_MODIFY` 重放区间内容），
  再由目录表重建所有表定义、主键索引和向量索引。

崩溃模型是进程被 `SIGKILL`，不模拟断电与磁盘损坏。恢复是幂等的：重放是按字节区间
覆盖，重复执行得到同样的结果。

## 6. 已实现的功能

- 表结构：`CREATE TABLE`（`BIGINT`、`VARCHAR(n)`、`VECTOR(n)`，一个 `BIGINT` 主键，
  最多一个向量列）、`CREATE VECTOR INDEX`、`DROP TABLE`。
- 数据操作：多行 `INSERT`、`SELECT`（投影、`SELECT *`）、`UPDATE`、`DELETE`。
- 条件查询：`=`、`<`、`<=`、`>`、`>=`、`AND`、`ORDER BY`、`LIMIT`。
- 向量检索：`L2_DISTANCE`（欧氏距离，不是距离平方）、精确 TopK、带过滤的 TopK、
  `ann` 近似检索。
- 事务：`BEGIN` / `COMMIT` / `ROLLBACK`，事务内可见自己的修改。
- 持久化：表定义与数据写入 `/data`，正常关闭与重启后内容一致；崩溃后恢复。
- 明确拒绝（返回错误码，不静默改义）：`NULL`、`JOIN`、聚合、子查询、`ALTER TABLE`、
  外键、嵌套事务、主键更新、`DISTINCT`、`OR`。

## 7. 已知限制

1. `DROP TABLE` 之外没有其它 DDL；目录是 id 为 0 的普通表，DDL 因此可以事务化。
2. 删除记录只释放槽位，不回收页内空间，删除密集的表会出现空间放大。
3. 行数超过 60000 的表不建立 HNSW 索引，`ann` 模式自动退化为精确扫描。
4. 缓冲池默认上限 512 MiB，可用 `VECTORDB_BUFFER_POOL_MB` 调整；数据量超过内存时
   依靠分页文件与缓冲池换页。
5. 单页最多 65535 条记录（槽位目录是 16 位计数）。
6. 多行 `INSERT` 的每一行都会经过一次行编码，没有做批量编码优化。
7. 近似检索在过滤选择性很高时可能需要扩大候选预算，极端情况下会退化为精确扫描。

## 8. 验证方式

| 验证 | 方式 | 结果 |
| --- | --- | --- |
| 公开用例 | 题包自带的 `protocol_check/run.py --image <镜像>` | 20/20 PASS（本地与远端服务器各跑一遍） |
| 协议握手 | `protocol_check/run.py --handshake-only` | PASS |
| 崩溃恢复 | 自写 `minivectordb/tests/crash_recovery.py`：SIGKILL、未提交事务、恢复途中再崩溃、提交后立刻崩溃、干净关闭 | 五个阶段全部通过 |
| 可见行数 | 插入 N 行后统计会话内与重启后的可见行数 | N = 5000 / 10000 全部可见 |
| 召回率 | `ann` 结果与 `exact` 结果逐条比对，分过滤组与不过滤组 | 均为 1.0 |
| 性能 | `minivectordb/benchmark/benchmark.py` | 见 [minivectordb-benchmark.md](minivectordb-benchmark.md) |

公开用例的规模很小（每张表几行），不足以覆盖分页、缓冲池换页和大数据量路径，
所以额外补了上面三项自测。性能数字见单独的性能记录文档。
